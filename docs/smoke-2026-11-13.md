## 结论（诚实版）

1. **没有证据表明 coach 在这些任务上带来收益**：它一次都没有触发。要验证教练收益，需要能产生失败/上下文压力/压缩的任务或更长的多轮会话。
2. **enforce（6 次工具调用上限）会伤害工具密集型任务**：`investigate-constant` 与 `investigate-duplicate` 成功率降到 66.7%/33.3%，整体成功率 −11.1 pt；token 并未下降。**不推荐默认开启 enforce。**
3. **observe 的“+20.9% token”不能归因于插件**：每组 3 次、token 范围 27k–75k，方差远大于中位数差异；且代码审计（S-02）已确认 observe 不改变模型输入。这里只能说明“n=3 的噪声很大”，不能说明插件有 20% 开销。
4. **D 组偏离预注册**：单轮 headless 任务里会话/单轮 token 预算要到轮末才结算，无法在当轮刹停；唯一能轮内生效的是 `turnToolCalls`。因此 D 用了 6 次工具上限，而不是“会话 token = 基线中位数 ×0.8”。这次结果验证了刹车机制，不代表预注册的 token 预算策略。
5. **默认值保持 `observe` 是正确的**：在真实流量上，先记录、后干预仍是唯一有证据支持的路径。
